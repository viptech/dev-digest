# RunCostBadge — специфікація фічі

**Дата:** 2026-07-28
**Статус:** до затвердження
**План реалізації:** [`../plans/2026-07-28-run-cost-badge-plan.md`](../plans/2026-07-28-run-cost-badge-plan.md)

## Задача

Показати, скільки коштував кожен ревʼю-прогін і кожен PR — у списку PR, у
таймлайні Agent runs, у плашці вердикту та в Run trace drawer. Нуль додаткових
викликів моделі: усі потрібні числа вже приходять у відповіді LLM.

## Стан на сьогодні

Вартість **уже рахується наскрізь**, але викидається:

- `reviewer-core` повертає `ReviewOutcome.costUsd`
  (`reviewer-core/src/review/run.ts:110,216`);
- для OpenRouter це **реальна** ціна генерації з `usage.cost`, а не оцінка
  (`reviewer-core/src/llm/openrouter.ts:107`);
- фолбек — живі ціни `PriceBook` (`server/src/platform/price-book.ts:34`), далі
  статична таблиця (`server/src/adapters/llm/pricing.ts:37`); невідома модель →
  `null`, а не нуль.

Коміт `d45ab0d` («remove per-PR/run cost, keep model pricing») вирізав саме
**збереження і показ**: колонку `agent_runs.cost_usd` (міграція
`0009_complex_runaways.sql`), поля `cost_usd` у контрактах `RunStats`/`RunSummary`
і плитку COST у трейс-дровері. Прайс-каталог моделей (`ModelInfo.pricing`, підписи
`$/1M` у пікерах) лишився на місці.

Отже, фіча — це «повернути й розширити», а не будувати з нуля. Нове порівняно з
тим, що було до `d45ab0d`: агрегована вартість на рівні PR, рядок у таймлайні і
рядок у плашці вердикту.

## Рішення

| Питання | Рішення |
|---|---|
| Поверхні | Усі 4: колонка COST у списку PR · рядок у таймлайні Agent runs · плитка COST у Run trace drawer · рядок у плашці вердикту |
| Колонка COST у списку PR | `SUM(cost_usd)` по **всіх** прогонах цього PR |
| Зберігання | Повернути колонку `agent_runs.cost_usd` новою міграцією; старі рядки лишаються `NULL` → «—» |
| Формат суми | 2 значущі цифри: `$0.06` · `$0.014` · `$0.0013` |
| Немає даних | `—`, **ніколи** `$0.00` |

## Що це НЕ

- **Не білінг.** Це орієнтир вартості прогону, а не рахунок. Для не-OpenRouter
  моделей число — оцінка за прайс-таблицею.
- **Не перерахунок на льоту.** Вартість фіксується в момент завершення прогону,
  щоб історія не «пливла» при зміні прайсу і не залежала від того, чи є модель у
  прайс-буку сьогодні.
- **Не новий виклик моделі.** Жодних додаткових запитів до LLM або до
  OpenRouter `/models` понад ті, що вже є.

## Компонент `RunCostBadge` (2 види)

Розташування: `client/src/components/run-cost-badge/` — спільний компонент
(kebab-case тека, як `app-shell/`, `diff-viewer/`), бо використовується і на
списку PR, і на PR Detail. Файли: `RunCostBadge.tsx`, `helpers.ts`, `index.ts`,
`RunCostBadge.test.tsx`.

```ts
type Props = {
  costUsd: number | null | undefined;
  tokensIn?: number | null;
  tokensOut?: number | null;
  variant?: "compact" | "detailed";   // default "compact"
  tokenFormat?: "pair" | "total";     // лише для "detailed", default "pair"
};
```

### Вид 1 — `compact`

Тільки сума: `$0.014`. Колонка COST у списку PR.

### Вид 2 — `detailed`

Токени + сума, у двох розкладках під наявні макети:

- `tokenFormat="pair"` → `$0.014 · 8.2K→1.3K` — рядок у плашці вердикту;
- `tokenFormat="total"` → `9 119 tok · $0.0013` — рядок у таймлайні Agent runs
  (сума `in + out`, групування розрядів вузьким нерозривним пробілом).

### Правила відображення (обовʼязкові)

1. `costUsd == null` → рендериться `—` кольором `var(--text-muted)`. **Ніколи**
   `$0.00` — інакше безкоштовна модель і невідома модель виглядають однаково.
2. Прогін, що ще виконується (`status !== "done"`), бейджа не показує взагалі.
3. Токени є, а вартості немає (модель поза прайс-буком) → показуємо токени,
   замість суми `—`.

### Форматування (`helpers.ts`)

- `formatUsd(n)` — 2 значущі цифри, мінімум 2 знаки після коми:
  `0.06 → "$0.06"` · `0.0135 → "$0.014"` · `0.00128 → "$0.0013"` · `1.5 → "$1.50"`.
- `formatTokenTotal(in, out)` → `"9 119"`.
- `formatTokenPair(in, out)` → `"8.2K→1.3K"`.

Наявний `formatTokens` у `RunTraceDrawer/helpers.ts:27` лишається як є — плитка
TOKENS у трейсі має власний формат `15k→1.2k`. Дровер лише додатково використовує
`formatUsd` для повернутої плитки COST.

## Дані

### Зберігання

`agent_runs.cost_usd` (`double precision`, nullable) — записується один раз, при
завершенні прогону, зі значення `ReviewOutcome.costUsd`.

Альтернативу «рахувати на льоту з токенів × прайс» відкинуто: прайс змінюється,
тож історична вартість «пливла б», а для моделей поза прайс-буком результат був
би `null` навіть тоді, коли OpenRouter повернув реальну ціну на момент прогону.

### Агрегація на рівні PR

Колонка COST у списку PR = `SUM(cost_usd)` по всіх `agent_runs` цього PR.
`NULL`, якщо прогонів немає або всі суми `NULL` → «—».

Це узгоджується з макетом: PR #482 має три прогони по ~$0.0013 і показує $0.014
у списку.

### Контракти

Контракти — вендорені у двох копіях (`server/src/vendor/shared/` і
`client/src/vendor/shared/`), синхронізуються вручну.

| Контракт | Поле | Тип | Чому |
|---|---|---|---|
| `RunStats` (`trace.ts`) | `cost_usd` | `z.number().nullish()` | Уже збережені `run_traces`-документи цього поля не мають, а `GET /runs/:id/trace` віддає jsonb як є (`server/src/modules/reviews/routes.ts:121`). `nullable` зламав би розбір старих трейсів і `server/test/contracts.test.ts:157`. |
| `RunSummary` (`trace.ts`) | `cost_usd` | `z.number().nullable()` | Колонка БД: значення завжди присутнє, може бути `NULL`. |
| `PrMeta` (`platform.ts`) | `cost_usd` | `z.number().nullish()` | Обчислюється лише на list-ендпоінті, як і сусідній `score`. |

## Поверхні

| Екран | Місце | Вид |
|---|---|---|
| Список PR | нова колонка COST перед UPDATED | `compact` |
| PR Detail · Agent runs | правий блок рядка прогону, над часом | `detailed`, `tokenFormat="total"` |
| PR Detail · плашка вердикту | рядок під `summary` | `detailed`, `tokenFormat="pair"` |
| Run trace drawer | четверта плитка Stats між TOKENS і FINDINGS | `formatUsd`, без компонента (плитка `Stat` уже є) |

Джерело даних для плашки вердикту: `ReviewRecord.run_id` зіставляється з
`RunSummary` зі вже наявного на сторінці `usePrRuns(prId)`
(`client/src/app/repos/[repoId]/pulls/[number]/page.tsx:46`). Немає збігу →
рядка немає.

## Ризики й межі

- **Старі прогони назавжди лишаються «—».** Бекфілу немає: токени в них є, але
  ціна на момент прогону невідома. Це свідомий вибір на користь чесності.
- **Точність для не-OpenRouter моделей** обмежена статичною таблицею
  `server/src/adapters/llm/pricing.ts`, де самі ціни позначені як приблизні.
- **Сума по PR росте від кожного повторного прогону** — це саме те, що потрібно
  («скільки цей PR коштував загалом»), але користувач може очікувати «вартість
  останнього ревʼю». Якщо це заплутуватиме — додати тултип із розкладкою по
  прогонах.
